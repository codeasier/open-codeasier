# PR Follow-up

Require a PR number and accept an optional focus. Read PR metadata, review threads, line comments, linked issues, code, tests, and contracts. Inspect the associated worktree and compare its patch with current `origin/main`; fetch first. Classify feedback as required, worthwhile, or out of scope, and explain disagreements with evidence. Before rebasing, force-pushing, resolving threads, or posting replies, show the exact action and obtain explicit confirmation. Apply the minimum correct changes, test them, commit only intended files, and report checks and mergeability.
